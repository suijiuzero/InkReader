# 1.13.0 多语言分章与磁盘导入验收

日期：2026-10-25。版本1.13.0，versionCode 63。Pixel_6 AVD，实际 API 37；构建／目标 API 34，最低 API 24。仅安装及测试模拟器，手机未更新。

## 六项实现

1. 扩展原生语言章标签和 Unicode 十进数字；规范化仅参与识别，保留原始标题。包含俄文、韩文、阿拉伯文、印地文、越南文、泰文等旧样本中的漏识别形式。
2. 纯阿拉伯数字、普通汉字数字、大写数字标题要求至少连续三项、上下留白和足够正文，并核对书首位置或与前章编号相接；孤立页码、年份、列表和引用不直接升级为章节。
3. 第1–2章等合章按起止区间参与查漏，区间内部不报缺章；仍不生成不存在的内容。
4. 无明确分卷时，中途从章标题变为数字序号等形式，结合成组连续性与正文长度补充识别；保留分卷重编号、上下篇与特殊章保护。
5. 单 TXT 预览和独立成书导入采用磁盘规范化、行索引及正文范围，按章节流式写入。完整源字节哈希与选项一致才复用方案；同 URI 换内容会失效，失败与取消清理原始临时文件。活跃仓库独占缓存会话，后续会话清理废弃索引。
6. 单书记住前40个展示分章点的纠错，重分章可沿用、暂时关闭或清除。仅匹配唯一的原始标题和附近正文摘要，改变或歧义时跳过；不跨书套用。记忆随本地书库备份，删除书时清理。

三语应用内说明、仓库使用说明、README、更新日志和测试工具说明同步。

## 样本与独立性

新增64份固定样本、132个预期标题：开发40份／77个标题，留出24份／55个标题。标注显式定义标题、规范化源行边界和完整段落，生成器不读取解析输出，输入／答案／分区清单有冻结哈希，来源组不跨分区。段落核对遵守导入既定的行尾空白规范化，不从输出修改答案。

另有旧金标准24份／81标题，以及旧154份格式与正文语料。旧语料3份空内容按预期拒绝，其余预期与正文块核对通过；1.12.0报告的15项识别限制本轮均达到原有 desired_titles，限制计数为0。这只说明该固定语料通过，不代表所有真实书源都能正确分章。

开发分区首次暴露〔〕标题、中文正文引用及段落行尾空格校验问题，分别修复规则或校验契约。开发通过后首次运行留出分区，24份全部通过，首次原始结果保留；未依据留出失败改写答案。后续全量复测中的这组已是已见数据，不应反复宣称为新的盲评。

## 审计与修复

- Unicode 大小写匹配补齐俄文大写标签，〔第N章〕后接副标题正常处理，合章包装保留编号区间。
- “第三章里说到…”等引用与明确步骤列表防误切；安卓旧样本 C147 暴露 “Chapter XIII. is an example…” 引用漏挡，补齐句点后的判断并加入回归。
- 磁盘行头只保留有界片段，正文长度判断使用完整索引长度，修复局部规则密度偏差；超长代码围栏使用真实长度，UTF-16分页和UTF-8流式写入不截断代理对。
- 磁盘与原路径共享书名推断；固定字数切口在没有移除水印时保留原始段落空行。
- 标题规范化从每行强规则循环中移出不必要的列表检测路径，修复无标题长文本耗时退化。
- 纠错记忆仅保存界面实际展示的接受／取消点，显式确认点可见于分析；模糊锚点不强制使用。
- 缓存始终核验完整源字节，仓库会话互相隔离；原子正文写入发生读取故障时保留旧文件。

早期开发、测试代码编译、模式对照和安卓 C147 失败均保留于本地审计日志，不计为最终通过；没有修改冻结答案迁就算法。
