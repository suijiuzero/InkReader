# 1.11.16 日语朗读修复

日期：2026-10-23。电脑已有本地晓晓/云希，但没有日语音色；原桥接固定 `Local-Xiaoxiao`，手机 TTS 初始化也固定中文。

## 行为

- 中英继续使用本地晓晓；含平假名、片假名（含半角片假名）的句子使用本地日语音色，优先七海 Nanami。只选本地音色，不调用 Edge/Azure 在线朗读。
- 新版安卓按章节前 2 万字符统计假名比例，至少 3 个假名、占汉字和假名总数至少 10% 时提供日语上下文。日语章节的纯汉字短句继续用日语；纯英文句子继续用晓晓。正文和下一句预取都携带语言。
- 手机 TTS 按章节选择日语；缺少日语数据时暂停并提示，不继续用中文误读。保留既有中英回退行为。
- 连接测试显示电脑是否有日语能力；听书面板新增“试听日语”。后端状态文字改为“本地自动语音”，避免日文使用七海时仍显示正在用晓晓。

## 本机安装

使用已有适配器登记的 ASCII 语音目录 `%LOCALAPPDATA%/InkReaderOffline/Voices/`，新增 `Nanami` 子目录。原晓晓、云希、注册表和配对文件保留。已重启本项目电脑桥接，身份与配对码保持不变，健康接口返回 `zh-CN/en-US/ja-JP`。

可复用的安装工具为 `tools/natural-voice/install_japanese_voice.py`。固定包为 `MicrosoftWindows.Voice.ja-JP.Nanami.1_1.0.4.0_x64__cw5n1h2txyewy.Msix`，73,813,757 字节；本次验收固定 SHA-256 为 `c19bc53946846b5f6964e10bd45263989ca768e05dffb4fbe4f3293bdd74f92a`。下载来源为适配器作者链接的 NVDA 镜像，哈希用于锁定本次测试包，不冒充微软发布的校验值。检查包身份、CRC、条目路径和解压预算后安装；已有 Nanami 目录不覆盖。

## 验证

- 140 项 JVM 测试通过，包含日语章节上下文、纯汉字短句、中英保持及半角假名回归。
- 6 项 Python 桥接测试通过，含鉴权、大小/参数边界、语言路由与非法语言值。
- 主 APK 和 AndroidTest APK 构建成功；静态检查 0 错误、47 条既有警告、11 条提示。
- 真实 SAPI 分别合成中、日、纯汉字日文、英文：实际音色为晓晓/七海/七海/晓晓；音频时长约 3.97 / 7.05 / 0.94 / 3.89 秒，均为可解码非静音 WAV。
- 正在运行的电脑服务验证旧请求格式（未传 language）的日文，以及显式 `ja-JP` 的纯汉字请求，均返回 200 和有效 WAV。无需给旧客户端增加字段即可朗读普通含假名的日文。
- 模拟器 Pixel_6（Android 17/API 37）经 ADB 转发已验证安卓端中日合成、MediaPlayer 播放完成、关闭开关和错误配对码拒绝。最终日语样本还按 UI 相同的 1.0 语速复测通过。
- 真实界面完成“测试连接 → 试听日语 → 播放完成”和晓晓试听回归；截图已人工查看。“Start reading”启动合成日文书的正文朗读，面板持续显示“Reading aloud / 电脑 · 本地自动语音”；随后执行暂停、继续、下一句及停止，测试未留在后台播放。
- 虚拟网关 `10.0.2.2` 路径出现间歇断流，广播发现也未能稳定通过；最终模拟器验收采用仅限 `emulator-5554` 的 `127.0.0.1:37262` 转发，不把此结果当作真实 Wi-Fi 发现通过。中途仪器测试的异步配对写入未落盘，导致面板仍沿用旧网关；已通过实际面板重配并读回地址确认，测试辅助程序也增加同步落盘。此为测试配置问题，不伪报为日语合成缺陷。
- 最终产物 SHA-256 与模拟器实际安装的 APK 一致，确认验证的是同一安装包。

实际结果和音频位于忽略目录 `app/build/audit/japanese-voice-2026-10-23/`，包含 `sapi-results.json`、固定测试 WAV、安卓检查输出与 UI 截图；不包含配对码。此轮只在模拟器安装 APK，未安装或操作用户手机。

## 限制

全文都是汉字、完全没有假名时，无法可靠自动区分中文和日文；中日混写的单句按一个音色朗读，不做词内切声。旧 APK 没有整章语言提示和新增日语试听按钮，需要新版才能使用这两项。手机本身的日语朗读仍取决于所装 TTS 引擎的日语数据。
