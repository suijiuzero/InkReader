## 更新日志

### v1.10.10（本次：导入与解析健壮性加固）

这一版没有新增可感知的功能，主要是把几处「极端输入下会出问题」的地方收口，日常使用没有变化：

- **超大文件不再拖垮 App**：导入单个文件超过 200MB 时直接给出「文件过大」提示，而不是先整个读进内存导致卡死或崩溃；DOCX / EPUB 解压时对压缩包内的单个条目也加了体积上限，避免畸形压缩包撑爆内存。
- **删除更可靠**：删书、删章的多步数据库操作改为一个事务，中途出错整体回滚，不会留下「书没了、章节还挂着」这类残缺数据；删除正文文件失败也不影响删除本身完成。
- **发布签名可切换**：在工程根目录放 `keystore.properties` 即可使用正式签名打包；不提供时仍回退调试签名，行为与之前一致。

> 老版本的用户数据没有任何变化，升级即可用。

字号、行距、段间距、字间距、页边距、字体、主题、翻页方式、翻页动画、首行缩进、屏幕亮度、朗读参数，**在任何一本书里改完，别的书也是这一套**，回到书架外观也跟着变。不再按书分别记，阅读器设置面板底部原来的「设为全局默认 / 恢复全局默认」两个按钮也随之取消。

### v1.10.8（翻页动画新增「覆盖」与「仿真」，翻页改为整屏）

「翻页动画」现在有四档，顺序是 **平移 / 覆盖 / 仿真 / 无动画**：

| 档位 | 效果 |
|---|---|
| 平移 | 两页一起滑动（原来的效果） |
| **覆盖** | 下一页先完整铺在底层不动，当前页在上层像被抽走一样整体平移出去，逐渐露出新页；不做变形、不加折痕与重阴影，干净、快 |
| **仿真** | 当前页像纸一样被折过去，露出下一页；折过去的纸背**能透出旧页的字**（镜像文字压一层纸色），折线上有高光、折痕旁有投影 |
| 无动画 | 立刻切换，不做缓动 |

**覆盖 / 仿真的操作方式**：左右拖动跟手（覆盖=旧页跟着手指移走，仿真=折线跟着手指走；拖动不足半页回弹，够了就翻过去；快速甩动按速度决定），点击屏幕左右边缘也能翻。到达书首/书末或正文还没排好时会自动不响应，不会出现空白页。

**翻页改成了「整屏」**：页眉（返回 + 章节名）和页脚（页码 / 百分比）现在是**每一页自己带着走的**，翻页时跟着整页一起动，而不是正文在页眉页脚之间挪动 —— 四档都是这样。文字位置、分页结果、页码统计和以前完全一致（页眉页脚占的位置在排版时照样留白）。

**实现上的两点取舍**（写在这里免得以后误会）：

- 仿真是**二维折页**：折线是竖直的，纸背只做镜像正文 + 纸色压暗，**不是三维卷曲**，也没有纸张弯曲的弧度。要升级成三维只改折页几何那一处，其它调用点不用动。
- 覆盖与仿真都**不走横向分页器**（旧版删掉的那两种就是因为画在了分页器里、绘制顺序压不住旧页才被判不值）。现在这两档有自己的一层绘制，绘制顺序自己控，所以「旧页压在新页上面」这件事才做得成。两者共用同一套叠层、手势与页码提交，只有「旧页怎么离开」不同。

> 升级提示：很老的版本存过「卷曲（CURL）」设置，这个值在新版里没有对应项，会自动落回「平移」，需要到「设置 → 翻页动画」里重新选一次；「覆盖」这个名字沿用旧名，老设置能直接对上。

### v1.10.7（本次：新增 Markdown / PDF / HTML / EPUB 导入，章节识别支持英语 / 日语）

**从「只能读 TXT 和 docx」扩到六种格式**，同时把解析这件事收拢成一套统一的管线。

| 新增格式 | 怎么解析 |
|---|---|
| `.md` / `.markdown` | 按 `#` 标题层级分章；**保留 Markdown 排版**（标题、粗体、斜体、删除线、行内代码、列表、引用、代码块、表格、链接、任务列表），YAML 头信息里的 `title` / `author` 用作书名作者 |
| `.pdf` | 用 **pdfbox-android** 提取文字（系统自带 API 只能把页面画成位图，拿不到文字）；按页面边界组织阅读顺序，按字号识别标题，每页重复的页眉页脚自动剔除 |
| `.html` / `.htm` | 提取 `<title>` 与正文，丢掉 `script` / `style` 等无关内容，`h1~h6` 转成章节层级 |
| `.epub` | 解析容器与 OPF，**按 spine（阅读顺序）逐章**提取 XHTML 正文 |

**三件配套的事**：

1. **统一解析架构**：格式识别（文件头魔数 + 内容嗅探）与解析器解耦，导入链路只调一个入口。原有的 TXT / docx 解析逻辑一行没动，只是套了层适配壳 —— 老格式的导入行为完全不变。
2. **错误提示统一管理**：所有解析器共用同一套文案。导入 `.zip` / `.xls` / `.ppt` 这类不支持的文件，会明确说「**暂不支持该文件格式（ZIP 压缩包）**」，而不是笼统的「导入失败」；`.doc` 会提示先另存为 `.docx`；文件损坏、内容为空、PDF 加密、疑似扫描件各有各的说明。
3. **批量导入结果明细**：一次导入多个文件时，只要有失败项，就弹一张明细表 —— **哪些成功（各几章）、哪些失败、失败原因**逐条列清楚。

> 代价：PDF 解析引入了 pdfbox-android（纯 Java，无 so、无 AWT），安装包会增加约 4~5MB；Markdown 解析引入了 commonmark-java（纯 Java，无 so、无 Android 依赖，约 300KB），体积影响可忽略。

**Markdown 现在是「格式化阅读」而不是「去标记」**（新增）：

以前导入 `.md` 是把粗体、反引号这些标记直接删掉，只留纯文本。现在改成**保留排版**：

| 类别 | 支持内容 |
|---|---|
| 标题 | H1–H6，字号逐级递减、加粗，前后留白更大 |
| 行内 | **粗体**、*斜体*、~~删除线~~、`行内代码`（等宽 + 淡底色） |
| 块 | 段落间距、连续空行压缩、`---` 分隔线 |
| 列表 | 有序 / 无序 / 嵌套列表，项目符号与序号画在左侧留白里 |
| 引用 | 引用块与嵌套引用，左侧一条竖线 |
| 代码块 | 围栏与缩进式代码块，保留缩进与换行，等宽字体 + 淡底 |
| 表格 | 保留行列结构，等宽对齐；过宽时自动换行而不是挤成一团 |
| 链接 | `http` / `https` / `mailto` 链接着色可点，点按用系统打开；其它协议退化成普通文字 |
| 任务列表 | `- [x]` / `- [ ]` 显示成 ☑ / ☐ |
| 图片 | 正文里显示为「［图片：替代文字］」占位（不联网加载） |

排版**跟随阅读器的字体、字号、行距、主题和背景设置**；标题层级照旧参与分章与目录跳转；格式化内容正常参与分页、翻页与阅读进度记录。

> 关键点：格式不只在导入时保留，**也贯穿分页**。一段加粗文字跨到下一页时两页都保持加粗，代码块被切开也不会丢缩进 —— 分页引擎按「块」来量高度和缩进，渲染端用同一套规则绘制。
>
> 实现方式：正文仍然是纯文本（朗读、搜索、选区、进度全都按字符偏移工作，一个字没改），格式化信息作为「样式覆盖」另存一份，两者偏移严格对齐；对不上时自动退回纯文本阅读，绝不会因为样式坏了导致整本书打不开。

### v1.10.6（本次：正文里提到「第X章」不再被误判成章节标题）

**问题**：如果正文里出现「一本书的第一章」这类**引用**，会不会被当成分章标题、把一章切碎？

**先说结论：绝大多数情况不会**，因为识别标题本来就有 4 道关卡：

1. 标题模式要求**整行匹配**（`^第X章 …$`）—— 正文里「…那本书的第一章…」这种行，**行首不是「第X章」**，直接不匹配；
2. 标题行**长度 ≤ 44 字**（正文句子通常更长）；
3. 标题行**不以句末标点结尾**（。！？…"）—— 正文句子几乎都带；
4. 要求**独占一行**（前后有空行，或下一行明显是长正文）；
5. 还要够 **≥2 个**强标题才会走「按章拆分」，否则退回按字数切。

**仍会漏的一种**：一行**以「第X章」开头、又不带句号**的正文，例如独立成行的

```
第一章里提到的那个名字
```

这种会被误当成标题。v1.10.6 补了第 6 道关卡：**看「第X章」紧跟着的那个字** —— 跟着「的 / 里 / 中 / 是 / 有 / 说 / 在 / 和 …」这类连接词，就判定为**正文在引用某一章**，不算标题。

| 行 | 结果 |
|---|---|
| `第一章 初见`、`第12章 破境`、`第十二章`、`第一卷 风起` | ✅ 标题（正常拆章） |
| `第一章里提到的那个名字`、`第三章的约定` | ❌ 判为引用，不拆 |
| `他翻开了那本书的第一章` | ❌ 行首不是「第X章」，本来就不匹配 |
| `第一章 的约定` | ❌ 判为引用（真标题不会以「的」开头） |

（这 10 个用例我都在本地按同一套正则跑过，结果与预期一致。）

### v1.10.5（单个文件导入也自动按章号排序）

**你问的那个情况：只导入一个文件、但文件里的章节是乱的 —— 之前不会自动排。**

原因：自动排序只接在「**合并导入（多文件）**」那条路径上；**单个文件**走的是另一条路（`各自成为一本书` → 解析文件内章节），解析出来是什么顺序就按什么顺序建章，乱序就一直是乱序。

现在：**每个导入的（每本）书都会在导入结束时按章号排一遍**，包括：

- 单个文件导入；
- 多文件「各自成为一本书」（每本各自排）；
- 多文件「合并为一本书」（这个 v1.10.3 已经有了）。

安全性：排序前会先比较，**顺序没变就完全不写库**，所以正常的书导入后不会有任何变化；只有真的乱序（章号能解析出来、但排列不对）才会被纠正。

另外，单文件导入的对话框里现在会明说这一点：「会自动识别文件里的「第X章」标题拆成章节，并按章号排序 —— 文件内部章节顺序乱掉也能纠正过来。」

> 提醒：排序依赖**章节标题能解析出章号**（`第12章`、`第十二章`、`Chapter 12`、`Chapter One`、`第12話`、`003 xxx`、`28` 这些写法都认）。如果标题里没有任何编号，那就无从判断先后，只能保持原顺序 —— 这种情况请用章节管理的「上移 / 下移」手动调。

### v1.10.4（修「章节管理里删掉整本后一直转圈」）

**现象**：从阅读器进章节管理删掉整本书 → 页面转圈圈，但其实书已经删了；手动手势退到书架就一切正常。

**原因**：删除成功后我只做了「**返回上一级**」，而上一级正是**那本刚被删掉的书**的阅读器 —— 阅读器加载不到书，就一直停在 loading 转圈。

**修法（两道保险）**：

1. 删除整本书后**直接回书架**（一路弹到底），不再落回那本已经不存在的书；
2. 阅读器自己也加了兜底：**加载完成但书不存在**时不再转圈，而是显示「**这本书已经被删除了**」+ 一个「返回书架」按钮 —— 这样不管从哪条路径把书删掉，都不会再出现死转圈。

### v1.10.3（智能解析合并后自动按章号排序）

v1.10.1/1.10.2 只做了「**文件之间**按文件名章号排序」，而 **文件内部拆出来的章节顺序、以及"单章文件"和"合集"交错的边界**并没有保证 —— 你要的「智能解析自带排序」缺的就是这一步。

现在：**合并导入时选了「智能解析」，成书后会再按章号把整本排一遍**（走的就是章节管理里那个「自动排序章节」的同一套逻辑）：

- 合集文件内部拆出来的 1~9 章、和单独文件带来的第10章，最终一定按 1→2→…→10 排好，不管文件是哪种顺序选进来的；
- 前置内容（序、楔子…）在最前，后记/番外/解析不出章号的在后（保持相对顺序）；
- 顺序本来就没变的话不写库，不会白折腾。

> 「追加文件为章节」不走这一步 —— 追加时是**按章号插到对应位置**（只动新加的，不打乱你手动调过的顺序），两者行为不同是有意的。

### v1.10.2（修智能解析把「节」当章拆 + 修对话框按钮被挤出屏幕）

**一、智能解析：不再把「第X节」当章来拆**

v1.10.1 的判据是「分片标题里的章号有两个以上不同的值就拆」，而解析器**把「第X节」也当章节标题**，于是一个「第10章」里含三节的文件被拆成了 **3 章** —— 你要的是**一整章**。

现在判断「是不是合集」**只认「章 / 回 / 卷 / 集 / 部 / 篇 / 幕 / 折」这一级，不认「节」**（另外补了英文 `Chapter N` 的识别）：

| 文件内容 | 智能解析结果 |
|---|---|
| 第1章…第9章（合集） | 拆成 9 章 ✅ |
| 第10章（内含第一/二/三节） | **整篇一章** ✅ |
| 内部没标题、被按字数切成几段 | **整篇一章** ✅ |
| Chapter 1…Chapter 20 | 拆成 20 章 ✅ |

> 注意：文件**内部**还是一样的解析规则（「第X节」仍会被识别为章节标题），只有**智能解析的"要不要拆"这一步**改用严格判据。如果你确实想按「节」拆，选「一律解析文件内章节」即可。

**二、修「导入对话框底下的按钮不见了」**

`InkDialogShell` 这个对话框壳的内容区**不能滚动**，选项从 2 个变成 3 个之后，底部那行「取消 / 开始导入」被挤到屏幕外了。现在：

- 给壳加了**独立的按钮槽**（映射到对话框自己的按钮区，**永远可见**，不会被长内容挤走）；
- 内容区改为**超过 460dp 可滚动**，选项再多也够得到；
- 导入对话框、追加文件对话框都改成这个结构。

### v1.10.1（章节划分新增「智能解析」）

**问题**：一次选了两种文件 —— 一个 **1~9 章的合集**、一个**单独的第10章** —— 原来两个选项都不对：

- 「解析文件内章节」：第10章那个文件内部没有章节标题，解析器会**按 1.8 万字兜底切成好几段**；
- 「每个文件作为一章」：合集就变成**一整章**，里面塞了 9 章。

**现在新增第三个选项「智能解析（推荐）」，并且设为默认**：**逐个文件判断**，文件里确实是一章一章分好的就拆成多章，否则整篇作为一章（章名取文件名）。

> 上面那两件事合起来导 → 合集拆成 **1~9 章**，单独的 **第10章 整篇成为一章**，顺序也对（按章号插入）。

怎么判断「是不是真按章节排好的」？两个判据：

1. 各分片标题解析出的章号有**两个以上不同的值**（真章节几乎总是如此）→ 拆；
2. 分片标题里**没有「（2）（3）」这种兜底后缀**（按字数兜底切分才会加）→ 拆。

所以「合集」会拆开，而「第10章 xxx」即使内部没标题、被兜底切成几段，也不会被误拆成好几章。

**追加文件为章节**那里也换成了同样三个选项，默认同样是智能解析。

### v1.10.0（追加章节自动插到中间 + 章节自动排序）

**1. 追加文件为章节时，按章号插到正确位置**

以前往书里追加章节一律**扔到末尾**。现在如果追加的文件名带章号，会**插到对应位置**：

> 已有 `第1章`、`第3章`（中间缺第 2 章）→ 追加 `第2章 xxx.txt` → 结果自动变成 **1 → 2 → 3**。

- 只移动**新追加的章节**，已有章节之间的相对顺序**不动**（所以不会把整本重排一遍）；
- 一次追加多个、章号打乱的，也按章号从小到大依次插好；
- 解析不出章号的新章节保持追加在末尾，不会丢。

**2. 章节管理 ⋮ 新增「自动排序章节」**

给已经**打乱**的书用：一次把整本按章节标题里的「第N章」重排。规则：

| 情况 | 排到哪 |
|---|---|
| `序 / 序章 / 序言 / 自序 / 楔子 / 引子 / 前言 / 题记 / 引言 / Prologue / プロローグ…` | 第一章**之前** |
| `第X章 / 第X话 / 第X节 / 第X卷…`、`Chapter / Part / Book / Volume / Episode + 编号`（阿拉伯、全角、中文/日文汉字数字、罗马数字、英文数字单词都认） | 按编号**数字**升序（`Chapter 10` 在 `Chapter 2` 之后） |
| 解析不出章号的（含 `幕間 / Interlude` 这类位置不固定的） | **钉在原位**，既不前移也不后甩 |
| `后记 / 后序 / 尾声 / 终章 / 结语 / 番外 / 附录 / 外传 / Epilogue / あとがき…` | **最后** |

> 只动「能解析出章号」的章节：把它们按编号升序**填回原来占据的那几个位置**；认不出章号的原地不动。旧版把认不出章号的统一排到中后段，`幕間` 这类夹在正文章节之间的内容会被排错 —— 现在不会了。

- 点之前会弹确认框，把规则和章节数说明清楚；
- **章节里的标签、笔记会跟着章节一起移动**（底层重排时会同步改标记的章号），不会串位；
- 已经有序的书点它不会有任何变化（会先比较，顺序没变就不写库）。

### v1.9.4（多文件导入按文件名里的章号排序）

一次选很多个文件时（比如把一本书拆成 52 个「第N章 xxx.txt」），**系统文件选择器给的顺序往往是乱的**（甚至倒序）。现在导入前会先解析文件名里的章号并据此排序：

- 认这些写法：**`第52章`**、`第51回`、`第十二章`（中文数字也认，支持「二十三」「一百零五」）、`003 破境.txt`、`12、威胁.txt`、以及文件名本身就是一个数字；
- 解析出章号的**按章号升序排在前面**；解析不出来的**保持原相对顺序排在最后**（不会因为排序丢文件）；
- 章号相同时用文件名兜底比较，结果稳定、可复现；
- **合并为一本书**时，章节顺序就是排完的顺序，章节标题取自文件名（`第52章 取舍之间`）；
- **各自成为一本书**时也按同样顺序建书，于是书架上「最近导入」的排列也跟着有序。

> 例：乱序选入 `第52章…` `第25章…` `第50章…` `第28章…` `第51章…` `第32章…`，导入后章节顺序是 **25 → 28 → 32 → 50 → 51 → 52**。

### v1.6.0（删掉覆盖 / 仿真，点击边缘翻页带动画）

**删掉「覆盖」和「仿真」两种翻页动画**，只保留 **平移 / 无动画**。

原因是它们跟分页引擎打架：这两种效果的诉求是「**旧页压在新页上面**、跟着手指滑走」，而 `HorizontalPager` 的绘制顺序是**按页号递增**（页号大的盖住页号小的），靠改位移根本做不出来 —— 只能把旧页单独提到 pager 之上再画一层，于是状态变成两套（谁在上、方向、被揭开的是哪一页），还各自带出一串边界问题（两层同时画文字会「重叠」、缩放会让下页从两侧露出来、静止与拖动期间要切换画法……）。连着几版都在这个坑里打转，实测收益不值这个复杂度，**直接删掉**：需要「旧页在上」的效果就该换分页实现，而不是在 pager 上打补丁。

> 旧版本里存过 COVER / CURL 的设置**会自动回落到「平移」**（读取时遇到不认识的枚举名取默认值），不用手动改。

**点击屏幕最左 / 最右翻页，现在跟着翻页动画走。**

以前点击边缘是**硬切**（`scrollToPage`，一帧跳过去，没有任何过渡），手势拖动才有动画，两者观感不一致。现在：

- 点击左右边缘 → **带动画滑过去**（用与手势一致的翻页动画）；
- **音量键翻页**同样带动画；
- 跳转（目录、搜索结果、批注定位）和改排版重排后**仍然直接对齐**，不做动画 —— 那些场景要的是「立刻到位」。

选了「无动画」时，点击边缘和音量键也都是立刻切换。

### v1.5.3（修「新页好像压在旧页上面冒出来」—— 仿真去掉缩放）

**症状**：旧页确实在上层了，但**有时候新页会很快冒出来、看着像压在旧页上面**：往左翻时左边先冒出来，往右翻时右边先冒出来。

**根因**：我为了让「仿真」看起来像纸被掀起，给上层那页加了一个**以页面中心缩放**的效果（`scaleX/scaleY = 1 - 0.08×进度`）。页面一缩小，**它的左右两条边同时往里收**，于是下面那页从**两侧**都露出来了 —— 露出来的那侧正好是旧页本该盖住的那边，看起来就是「新页在旧页旁边冒出来、像在上面」。覆盖模式没有这个缩放，所以只有仿真会出现（这就是「有时候」的来源）。

**修法**：**仿真不再做任何几何变形**，纸感只用阴影表达（仿真 0.40，覆盖 0.22，都比之前更明显一点）。位移逻辑一个字没动。

**定位过程**（这次没猜）：`Log` 被这台机器的系统策略挡掉了（连 Error 级都没有），所以我做了个**带颜色标记的诊断版**（被揭开的那页染冷色、上层那页染暖色），用 `adb` 在慢速滑动过程中连拍截图，再用 Python 按列统计 R-B 色差，把每一帧里两页各自的位置量了出来：

- 覆盖 · 前翻：暖色 `0..1072 → 0..824 → 0..576`（旧页右边缘往左收），冷色从右侧长大 ✓
- 覆盖 · 后翻（干净的一次）：冷色从左侧 `72..216 → 72..464 → 72..712` 长大，暖色往右让开 ✓

两个方向、两种模式都对，唯独带缩放的仿真会让冷色铺满整屏 —— 与推测完全一致。另外把 `PagerState` 的源码掏出来核对了坐标约定：`currentScrollOffset = (currentPage + currentPageOffsetFraction) * pageSize`，正的 fraction 就是往后翻，我的位移公式和这个一致。

> 顺带说明：**「仿真」不是真正的卷页**，是「覆盖 + 更重的翻页阴影」。真卷页要对页面做曲面变形（canvas/shader），是另一个量级的工作。

### v1.5.2（重做覆盖 / 仿真 —— 旧页在上、往左滑走）

上一版把覆盖做反了：我让**新页压着旧页滑进来**，而正确的「覆盖」是**旧页压在新页上面、跟着手指往左滑走**，新页早就铺在底下等它揭开。仿真之所以还会「正文重叠」，根因也在这里：

**`HorizontalPager` 的绘制顺序是按页号递增的**（页号大的盖住页号小的）。上一版为了做「揭开」效果，把**新页**（页号更大）钉在视口里不动，结果它反而画在旧页**上面**，两页文字就叠在一起了。**靠改位移做不出「旧页在上」**——页号顺序是定的。

这一版改成**两层**：

- **下层**：所有页照常交给 pager，但拖动期间把「被揭开的那一页」的位移抵消掉，让它**钉在视口里**不动；
- **上层**：把「正在被翻走的那一页」单独提到 pager **之上**再画一层，跟着手指 1:1 移动，带自己的不透明底色。因为它是后画的，天然压在下面那页上面；
- 同时让下层里那份「正在翻走的页」**完全隐形**（`alpha=0`），避免同一页被画两份 —— 那样同样会看起来像文字重叠。

揭开方向由翻页方向决定：往右翻时旧页往左走、揭开的是下一页；往左翻时旧页往右走、揭开的是上一页。纸感：**覆盖**是一道轻阴影（0.22），**仿真**阴影更重（0.40）。**仿真不是真正的卷页仿真**（真卷页要用 canvas 做曲面变形），是「覆盖 + 翻页阴影」的近似 —— 早期版本给它加过一个「略微缩小」的形变，v1.5.3 已移除（原因见 v1.5.3 说明）。

拖动期间下拉打标签会暂时禁用（避免和翻页手势打架），松手后恢复。

### v1.5.1（修翻页动画下的正文重叠 + 恢复默认按钮）

**修「覆盖 / 仿真时两页正文直接叠在一起」** —— 这一版先修掉了两个表层原因（页面没有实底、以及我用 `alpha` 让旧页「变暗」导致下层文字透上来），**但真正的原因在 v1.5.2 才查清**：pager 的绘制顺序按页号递增，被钉住的新页反而画在旧页上面。

### v1.4.2（三个行为开关 + 修「正文最后一行被截断一半」）

**修复：左右翻页时，页面最底下那一行字被竖向切掉一半。**

根因有两个，都在分页器里，而且互相叠加：

1. `continuation`（续排标记）**永远被设成 false**：分页器把段落切开跨到下一页时，没把「下一段开头是续排」标记出来。于是**渲染端**给每个跨页续排的段落片段都加了首行缩进（本来不该有）；
2. **分页器测量文本时用的是「不带首行缩进」的样式，渲染时却带缩进** —— 首行少放两个字，段落就可能多出一行，页面高度不够，最后一行溢出后被裁掉半截。

修法：修正续排标记；**首行缩进参与测量**（段落第一截带缩进量、续排那截不带）；行高取「名义行高」与「实测量一行的高度」中较大的那个，再留 1dp 余量。

**新增三个开关**（设置面板「首行缩进」下面）：

| 开关 | 说明 |
|---|---|
| 音量键翻页 | 收起工具栏时音量下/上翻页；呼出工具栏时恢复调音量（v1.3.2 加的功能，设置里一直没入口，这次补上） |

### v1.2.1

**修复「导入文档 → 选好文件 → 按确定却什么反应都没，再试一次又好了」**。根因不在导入逻辑，而在系统文件选择器这一段，共四处加固：

1. **不再相信标准契约的解析结果**。原代码用 `ActivityResultContracts.OpenMultipleDocuments`，它在 `resultCode != RESULT_OK` 时**直接返回空列表**；而某些 ROM（实测 vivo 自带的文件管理器选择器）会在用户已经选好文件的情况下回一个非 OK 的 resultCode，于是 App 拿到空列表就**静默什么都不做**——表现出来就是「按了确定毫无反应」。现在改成自己发起 `ACTION_OPEN_DOCUMENT`，**不看 resultCode**，只要返回的 Intent 里有 Uri 就认（`clipData` / `data` / `EXTRA_STREAM` 三条路都试一遍）。
2. **选择器被系统回收后自动接上**。打开选择器时墨阅在后台，实测这台手机的系统会 `am_app_frozen`（fast_freezer）甚至 `am_kill ... single-cleaner` 把进程冻结/杀掉，此时选择器的结果就永远回不来了。现在发起选择器前会把「我要选文件了」同步落盘，结果一回来就清掉；如果重进 App 时发现这个标记还新鲜（5 分钟内），说明上一次被系统打断了，会**自动把选择器重新打开**并提示一句「上次的文件选择被系统回收了，已重新打开」。
3. **选好的文件立刻落盘**：万一进程在「选完文件、还没点开始导入」之间被回收，重进 App 会把「导入 N 个文件」设置框原样恢复出来，不用重新选、不用重新填。
4. **`file://` 也能读了**：部分 ROM 的选择器回的是 `file://` 而不是 `content://`，现在读取时两条路都会走（ContentResolver → 直接 File），并会尽力把授权持久化。

> **顺带一个手机侧建议**（能明显减少被冻结/清理，后台朗读也更稳）：
> 把墨阅加入白名单 —— 设置 → 电池 → 后台耗电管理 → 允许「后台高耗电」；
> i管家 → 应用管理 → 权限管理 → 自启动 → 允许。

## 二、怎么把书弄进来

**方式一：应用内导入**

书架右下角「导入」→ 系统文件选择器里可多选 → 选完会问你怎么导：

- **各自成为一本书**：每个文件独立成书，自动识别章节
- **合并为一本书**：每个文件成为一章（或解析文件内章节，见下），书名可自定义

选「合并为一本书」后还会问**章节划分**：

| 选项 | 行为 |
|---|---|
| **智能解析（推荐，默认）** | 逐个文件判断：文件里真的按「第X章」分好了就拆成多章，否则整篇作为一章；**成书后按章号自动排序** |
| 一律解析文件内章节 | 每个文件都按内部「第X章」拆；没有内部标题时会按字数兜底切分 |
| 每个文件作为一章 | 不拆分，文件整体成为一章，章节名取文件名 |

> **多文件导入会按文件名里的章号自动排序**（v1.9.4）：一次选很多「第N章 xxx.txt」时，系统给的顺序往往是乱的，现在会解析出章号（`第52章`、`第十二章`、`003 破境`、`28` 这些写法都认）并升序导入；解析不出章号的文件保持原顺序排在最后，不会丢。两种导入方式都会排序。

**方式二：从别的 App 打开**

在文件管理器 / 微信 / QQ 里长按 TXT / docx / md / pdf / html / epub，选「用其他应用打开」→ 墨阅，直接进导入流程。

**方式三：新建手写书籍**

书架右下角「新建」→ 填书名作者 → 创建后进详情页 →「新建空白章节」直接写；也可以「追加文件为章节」把已有的 TXT / docx / md / pdf / html / epub 并进来（同样会问章节划分方式）。

**关于「使用说明」**：本文件随安装包一起分发，安装后即可在 `docs/使用说明.md` 处查看；应用内没有「使用说明」入口。它以 Markdown 写成（`InkReader/docs/使用说明.md`），用任意 Markdown 阅读器打开即可。

**给书换封面**：进书籍详情页（阅读器右上角 ⋮，或书架列表右侧 ⋮）→ 右上角 ⋮ → **导入封面** → 选一张图 → 拖动/双指缩放调整 → 确定。想还原就再进这个菜单点**「恢复默认封面」**。

> **导入时按了确定没反应？**（v1.2.1 已修）
> 说明那一次的文件选择被系统回收了。现在有两种自愈：选好文件后进程若被回收，重进 App 会把导入设置框原样恢复；若是刚点开选择器就被回收，重进 App 会自动帮你重新打开选择器。
> 如果还是遇到，把墨阅加入系统白名单（设置 → 电池 → 后台耗电管理 → 允许后台高耗电；i管家 → 应用管理 → 权限管理 → 自启动 → 允许）能根治。

### 书架分组（v1.7.0 新增）

书多了以后可以分组收纳。**一本书最多属于一个分组**（分组是「收纳盒」不是「标签」，同一本书不会同时出现在两个分组里）。

**怎么建组**：长按书架上的任意一本书 → 进入多选（顶部会显示已选几本）→ 再点其它书加选 → 底部操作条：

| 操作 | 说明 |
|---|---|
| **新建分组** | 起个名字，选中的书直接进这个新组 |
| **移动到分组** | 放进已有分组（分组列表为空时会提示先新建） |
| **移出分组** | 从当前分组退回书架（在分组页里编辑时也用这个） |
| **删除** | 删书（会二次确认，和以前一样） |

**分组卡片长什么样**：和书籍卡片**同样的尺寸和样式**，封面位置是组内**最多 4 本**的封面拼成 2×2，下面一行组名 +「N 本 · 分组」。超过 4 本也只显示前 4 本。

**点进分组**：固定 **一行三本**的网格（书再多也不会更密、没有上限），点书直接开始读。右上角 ⋮ 有：

- **编辑分组** —— 进入多选，底部「移出分组」/「移动到别的分组」；
- **重命名**；
- **添加书籍** —— 从「不在本组」的书里多选加进来；
- **解散分组** —— 组内书籍回到书架，**书本身不会被删除**。

**列表模式**：分组在列表里占一行（左侧迷你 2×2 封面拼图 + 组名 + 本数 + 箭头）；点进去后组内也按列表呈现（跟随书架的视图设置）。

### 搜索书籍（v1.8.0 新增）

书架顶栏最左边是**搜索按钮**，点进去：顶部一个搜索框（自动聚焦键盘），输入**书名或作者**的关键字，命中的书以**卡片网格**呈现 —— 封面 + 书名 + 进度条 + 「N 章 · 已读 x%」。

- **点卡片**：直接开始读（从上次读到的位置继续）；
- **长按卡片**：进这本书的详情页（章节管理 / 导出 / 封面）；
- 搜索是**纯内存过滤**（书架本来就一次性读完所有书），所以是边打边出结果，不转圈、不卡。
- 搜索框右侧有清空按钮；结果是空的时候会明确告诉你「没找到「关键词」」。

## 三、支持的格式

| 格式 | 支持程度 |
|---|---|
| `.txt` | 完整支持。自动识别 UTF-8 / UTF-8（带 BOM）/ GBK / GB18030 / UTF-16 编码 |
| `.docx` | 完整支持。读取正文段落与 Heading 1-6 标题层级，标题自动变章节；表格降级为制表符对齐文本，图片替换为「〔图片〕」占位 |
| `.md` / `.markdown` | 完整支持（含**格式化阅读**）。`#` 标题按层级分章；标题 / 粗体 / 斜体 / 删除线 / 行内代码 / 列表 / 引用 / 代码块 / 表格 / 链接 / 任务列表都按原格式显示；YAML 头里的 `title` / `author` 用作书名作者 |
| `.pdf` | 支持**文字版** PDF。提取正文并按页面组织阅读顺序，按字号识别标题；每页重复的页眉页脚自动剔除。**图片型扫描件提不出文字**，会提示暂不支持 OCR |
| `.html` / `.htm` | 支持。提取 `<title>` 与正文，丢弃标签与脚本样式，`h1~h6` 转成章节层级 |
| `.epub` | 支持。解析容器与 OPF，按 spine（阅读顺序）逐章解析 XHTML 正文 |
| `.doc`（97-2003 老格式） | **不支持**，会明确提示。请先用 Word / WPS 另存为 `.docx` 或 `.txt` |
| `.zip` / `.xls(x)` / `.ppt(x)` / `.mobi` 等 | **不支持**，导入时会明确提示「暂不支持该文件格式（XXX）」 |

**章节自动识别规则**（所有格式通用，按可靠性排序）：

1. 解析器自带的标题层级：docx 的标题样式、Markdown 的 `#`、HTML / EPUB 的 `h1~h6`、PDF 的字号
2. 中 / 日：`第X章 / 回 / 節 / 节 / 話 / 话 / 巻 / 卷 / 集 / 部 / 編 / 编 / 篇 / 幕 / 折`（阿拉伯数字、全角数字、中文/日文汉字数字都认）
3. 英 / 日：`Chapter / Part / Book / Volume / Episode + 编号`（编号可以是数字、全角数字、罗马数字或英文数字单词，如 `Chapter 1`、`Part Two`、`Book I`、`Volume III`）
4. 特殊章节：`序章 / 楔子 / 引子 / 前言 / 后记 / 尾声 / 番外 / 终章 / 结语 / Prologue / Epilogue / Interlude / Afterword / 幕間 / 番外編 / プロローグ / エピローグ`
5. `1、标题` / `（1）标题` / `卷一 标题` / `巻2 标题` 这类编号行
6. 以上全不命中时，按每 1.8 万字在段落边界自动切分，保证任何文件都有目录

> 编号会统一解析成整数再排序（`Chapter 10` 排在 `Chapter 2` 后面，不是按字符串）；序章 / Prologue 这类**前置内容**排最前，终章 / 番外 / Epilogue 这类**后置内容**排最后，`幕間 / Interlude` 这种位置不固定的**钉在原位**，都不硬塞进数字序。正文里 `Chapter 1 is where…`、`第一章里提到的…` 这类**引用**会被识别出来、不当作标题。

带层级的格式（docx / Markdown / HTML / EPUB）优先用文档自带层级分章 —— **只有最浅的那一级标题**被当作章节分隔，更深的子标题保留在正文里，不会把章节切得支离破碎。

## 四、阅读器操作

**顶栏**（点击正文唤出）：左边 **`<` 返回首页**，接着是 **「第几章 + 章节标题」**（书名在第二行小字），右侧是「目录」和「⋮（章节管理）」。
**常驻页眉**（**不点也有**）：阅读页顶部一条窄条，`<` 返回首页 + 章节信息 —— 收起工具栏时一直可见，点开工具栏则让位给完整顶栏。**章首页显示的是书名**，从第二页起显示「第几章 章节名」；章首页的正文顶上还会有一块**大标题**（番茄那种）。
**底栏上方的章节进度条**（点开工具栏时出现）：左「上一章」／中间可拖动的进度条／右「下一章」，拖动时浮出「第 N 章 · 章节名」预览，**松手才跳章**；进度条点一下也能跳。
**页脚**：**`当前页/全书总页数`**（如 `1234/12311`）+ 右侧百分比。总页数是按当前排版把整本排一遍数出来的，改字号/行距后会自动重算，算完前显示 `—/—`。

| 手势 | 作用 |
|---|---|
| 点击正文任意处 | 唤出 / 收起顶部与底部工具栏 |
| **点击顶栏章节标题** | 进入书籍详情页（章节管理、导出 TXT、导入封面都在那里） |
| 左右滑动 | 翻页；**翻到本章最后一页继续往后滑，直接进下一章正文** |
| **点屏幕最左 / 最右** | **上一页 / 下一页**（左右各占正文宽度的 28%，中间区域是唤出工具栏；带动画滑过去） |
| **把正文页面往下拉** | **给这一页打标签；已有标签时松手即取消**（仅左右翻页模式） |
| 上下滑动 | 滚动；**滚到本章末尾自动接下一章** |
| **长按正文** | 选中一个词，顶部弹出批注操作条；**按住不放继续拖可以扩选** |
| **拖选区左右两端的竖条** | 拖哪一头就改哪一头，精确扩选 / 收缩 |
| **音量键** | 收起工具栏时：音量下 = 下一页、音量上 = 上一页（呼出工具栏时恢复调音量） |

**跨章连续阅读**（v1.2.0 新增）：

- 往后：本章最后一页继续往后滑 → 下一章直接滑进来；滚到底同理。
- 往前：翻到某章第一页再往前滑 → 回到**上一章末尾**（不是上一章开头）；滚动模式往回滚过头同理。
- 每次切章，屏幕中央会淡入淡出闪过新章节名（章序号 + 标题 + 共几章）；不想要可以在设置里关掉「切章提示卡片」。
- 整本书的第一章第一页再往前、最后一章最后一页再往后，会停在原地（没有更多内容了）。

**按页标签**（v1.3.0 新增，v1.3.1 改成下拉式）：

- 在正文上**把页面往下拉**（像番茄那样整页跟着手指下移）→ 顶部空隙里浮出标签提示：拉开时是「继续下拉，给这一页打标签」，拉过阈值变成实心色「松手给这一页打标签」。**松手**即打上标签（轻震动 +「咚」一声），页面弹回。
- 这一页**已经有标签**时，下拉提示变成「松手取消这一页的标签」，松手即取消。
- 页脚左侧会有一个小书签角标表示「本页已加标签」。
- 标签记的是这一页正文的字符位置，改字号/行距重新分页后依然跟着那段文字走。
- 点底栏「目录」→ 抽屉顶部两个页签：**章节** / **笔记**。「笔记」里是这些标签的卡片（**第几章 + 该页开头的一小段正文**），点卡片跳回那一页，卡片右上角可单独删除。
- 「笔记」页签同时列出**整页标签**和**段落标签**；长按正文打的高亮/笔记仍在「设置 → 笔记与书签」（那一页也有「标签」筛选）。
- 这个手势只在**左右翻页**模式下有效——上下滚动时下滑就是滚正文。

**批注操作条**（长按正文唤出）：

- 上排：**「整句」**（把选中范围扩到完整句子）、**「整段」**（扩到整段）、× 收起选区；
- 下排左侧：**四个颜色圆点** = 暖金 / 雾蓝 / 藕紫 / 苔绿高亮。**点已经生效的那个颜色 = 取消高亮**（生效的颜色带墨蓝描边和 ×），点别的颜色 = 换色；
- 下排右侧三个图标：
  - **书签图标 = 把这一段打成标签**（打过之后正文下方有一条蓝线、图标变实心墨蓝，再点即取消）；
  - **耳机 = 从这一段开始朗读**；
  - **笔记 = 引用这段原文写下想法**。

选区的**左右两端各有一根可拖的竖条**，按住拖动即可精确扩选/收缩；另外长按后**手指不松继续拖**也能扩选。

所有标签、高亮、笔记都能在「设置 → 笔记与书签」里按类型汇总查看（含「标签」筛选），点一下跳回原文位置；每张卡片右下角的删除图标可以删掉单条标记。

**底部工具栏**五个入口：目录 / 主题 / 朗读 / 搜索 / 设置。

## 五、排版设置

设置面板顺序：

1. **主题**：月白（默认）/ 纸白 / 护眼 / 深墨 / 纯黑 —— 五张色卡带「永」字预览，所见即所得
2. 实时预览条：当前字号行距下的真实渲染效果
3. 字号 12–32、行距 1.10–2.80、段间距 0–2.0、字距 0–0.10、页边距 10–36
4. 字体：**无衬线（默认）** / 衬线
5. 翻页方式：左右翻页 / 上下滚动
6. **翻页动画**（仅左右翻页时出现）：平移 / 覆盖 / 仿真 / 无动画
7. **首行缩进**、**音量键翻页**、**打标签音效**、**切章提示卡片** 四个开关（音量键翻页、音效、切章卡片默认都开）
8. 屏幕亮度（可单独调，也可跟随系统）
9. 设为全局默认 / 恢复全局默认
10. 这本书：笔记与书签 / 编辑本章 / 章节管理

> 字号·行距那张卡片的**最底部有一个居中的「恢复默认字号行距」**，一键把字号 19 / 行距 1.75 / 段间距 0.6 / 字距 0.02 / 页边距 20 调回出厂默认。
> 它和「恢复全局默认」不同：后者是回退到你保存过的全局设置，前者是无视你的全局设置、直接回出厂值。

**排版按书独立记忆**——A 书里调的字号不影响 B 书。想统一就点「设为全局默认」，想跟全局一致就点「恢复全局默认」。

所有设置实时生效，调节过程中正文立刻重排，且**不会把你甩回章节开头**，会停在原来读到的位置。

> 底栏「主题」图标点一下会**按顺序循环切换**五套主题：月白 → 纸白 → 护眼 → 深墨 → 纯黑 → 月白。

## 六、朗读（听书）

底部工具栏「朗读」→ 设置语速（0.5x–2.5x）、音调、起始位置（从本页继续 / 从本章开头）、定时停止（不限时 / 15 / 30 / 60 分钟 / 读完本章）→ 开始朗读。

朗读时：

- 正在读的那一句用主题强调色高亮，页面自动跟着翻
- 读完整章自动接下一章
- 通知栏有 上一句 / 播放暂停 / 下一句 / 停止 四个按钮，锁屏也能控
- 支持耳机线控（注册了 MediaSession）
- 息屏后台继续读，有 WakeLock 保证不被系统掐断
- 任何界面底部都有一条悬浮控制条，随时暂停

> **重要**：朗读用的是**手机系统自带的语音引擎**，App 本身不内置语音包。
> v1.3.2 修好了一个真问题：Android 11 起 App 必须声明软件包可见性才「看得到」系统引擎，
> 之前漏了这条声明，所以哪怕手机装了引擎也读不出来。现在如果打开朗读面板仍看到红色提示条，
> 说明系统里确实没有 TTS 引擎，去「系统设置 → 无障碍 / 辅助功能 → 文字转语音输出」装一个即可
> （Google 语音服务、讯飞语音、vivo/vivo语音引擎、小米语音引擎都可以）。

## 七、章节管理

进入方式：**阅读器右上角 ⋮**（v1.2.0 起直接进），或阅读器里点顶栏书名，或书架列表视图点右侧「⋮」，或阅读器「设置 → 章节管理」。

右上角「⋮」菜单：

- **整本导出为 TXT**
- **单章导出…**（弹出章节列表，点哪章导哪章）
- 修改书名与作者
- 追加文件为章节（会先问章节划分方式；**文件名带「第N章」的会按章号插到对应位置**，见 v1.10.0）
- **导入封面**（选图 → 拖动/双指缩放裁切 → 确定；裁切结果存进应用私有目录，不留原图）
- **恢复默认封面**（设过自定义封面后才出现）
- 新建空白章节
- **自动排序章节**（按章节标题里的「第N章」把整本重排；序/楔子在前、后记/番外在后，标签笔记跟着走）
- 删除整本书

每个章节行右侧「⋮」菜单：

- 阅读本章 / **导出本章为 TXT** / 编辑正文 / 重命名 / 上移 / 下移 / 删除本章

上移下移时章节里的书签高亮会跟着一起移动，不会错位。**自动排序**同样会带着标签/笔记一起移。编辑器里的正文**停笔 1.2 秒自动保存**，也可手动点「保存」，退出前一定落盘。

## 九、导出为 TXT

**入口**：章节管理页右上角「⋮」→「整本导出为 TXT」或「单章导出…」；章节行右侧「⋮」→「导出本章为 TXT」。

**导出后会发生两件事**：

1. 文件写进**系统「下载」目录**（`Download/书名.txt`），用任意文件管理器都能找到；
2. 紧接着**弹出系统分享面板**，可以直接发微信 / QQ、传到网盘或蓝牙发送。

**文件内容**：

```
书名
作者：某某           ← 作者为空则不写这一行

第一章 标题

正文第一段……

正文第二段……


第二章 标题

正文……
```

- **整本导出**：书名（+ 作者）作为文件头，之后每章一个标题加正文。
- **单章导出**：只有这一章的标题与正文，没有书名文件头，文件名是 `书名-章节标题.txt`。
- **不含任何批注**：书签、高亮、笔记一律不写进 TXT，导出的是一份干净的纯文本。
- 编码 UTF-8 **带 BOM**、换行 CRLF —— 传到电脑上用记事本打开也不会乱码或挤成一行。
- 文件名里的 `\ / : * ? " < > |` 会被替换成下划线，过长会截断。

**说明**：

- Android 10 及以上用的是 MediaStore，不需要任何存储权限；同名文件系统会自动加序号，不会覆盖你之前导出的。
- Android 9 及以下写公共下载目录需要「存储权限」，会弹一次授权；**不给也照样能导出**，只是不落下载目录，可以直接在分享面板里另存。
- 分享用的临时副本放在应用缓存目录里，每次导出会自动清掉上一次的。

## 十、技术说明

- Kotlin + Jetpack Compose（Material 3），单 Activity 架构
- 存储：SQLite（手写 DAO，没用 ORM / 注解处理器，减少构建期风险）+ 正文以 UTF-8 文件存在应用私有目录，数据库只存索引；**自定义封面**也存私有目录（`filesDir/covers/`），数据库只存文件名。书籍库版本 v1 → v2 用 `ALTER TABLE books ADD COLUMN cover_path` 迁移
- **docx 解析没用 Apache POI**：POI 在安卓上要拖进 `javax.xml.stream`、AWT 等一大堆桌面端依赖，包体涨 10-15MB 且容易在 dex 阶段出问题。这里直接用系统自带的 `XmlPullParser` + `ZipInputStream` 解析 `word/document.xml` 和 `docProps/core.xml`，拿到同样的正文与标题层级，零额外依赖
- **解析收拢成一条统一管线**：`DocumentFormat` + `FormatDetector`（文件头魔数 → 扩展名 → 内容嗅探，能把同为 ZIP 的 docx / epub / xlsx / 普通 zip 区分开）→ `DocumentParser` 接口 → 统一的 `ParsedDoc` 结果 → `ParseErrors` 统一文案。TXT 与 docx 的解析逻辑一行没动，只是套了适配器；导入链路（合并 / 分章 / 排序 / 落盘 / 建库）完全复用，新增格式不用碰这一层
- **markdown / HTML / EPUB**：Markdown 用 **commonmark-java** 出 AST（嵌套强调、围栏代码块、表格、嵌套列表这些结构逐条正则处理不对），只走一遍 AST 同时产出「阅读用纯文本 + 样式覆盖」；HTML 与 EPUB 共用一个**手写**容错 HTML 状态机（`h1~h6` → 层级、`script`/`style` 整段丢弃、实体与 `gbk` 声明都处理），EPUB 再按它 OPF 里的 spine 顺序取正文 —— 后两者没有引入任何第三方库
- **只有 PDF 和 Markdown 用了第三方库**（都是纯 Java，无 so、无 AWT）：PDF 用 pdfbox-android；Markdown 用 commonmark-java（核心 + GFM 表格 / 删除线 / 任务列表三个扩展，合计约 300KB）。系统 `PdfRenderer` 只能把页面渲染成位图、取不到文字，而 PDF 里的中文字体基本都是 CID 子集 + ToUnicode CMap，自己解析极易提出乱码。实现是覆盖 `PDFTextStripper.writeString` 逐词收集「文字 + 字号 + 基线」，按基线切行、按行距聚段、按字号众数判标题，再用「收集到的字形数 / 实际字形数」做完整性校验，比例异常就退回标准提取
- **解析失败共用一套文案**：损坏、内容为空、加密、疑似扫描件、不支持的格式，各由 `ParseErrorCode` 决定说明文字，避免每个解析器各写一套提示；批量导入则把逐文件的成败明细汇总到一张结果表里
- 分页用 `TextMeasurer` 按段落块贪心填充：段落放不下时精确定位到当前可用高度内最后一行的行尾切开，剩余部分顺延下一页，所以任意字号 / 行距组合都不会溢出页面
- **跨章无缝翻页的实现**：分页模式给 pager 的是「**上一章末页 + 本章各页 + 下一章首页**」这样的页槽序列，槽位数只由「前后是否存在邻章 + 本章页数」决定，邻章内容没排好时先占位，所以槽位下标始终稳定、不会跳页；用户滑到邻章衔接页时直接切章，而落点正是他刚刚滑进来的那一页，视觉上没有跳转感。邻章只排需要的那一页（`Paginator.paginate(maxPages = 1)`），离开的章节自动变成邻章缓存，因此来回翻章不重新解析、不重新排版。滚动模式同理，把「上一章 + 本章 + 下一章」的段落块拼成一条连续列表（key 带章节号保证唯一），视口整体越过本章边界时提交切章并按键锚定保持位置。
- **按页标签的实现**：标签就是一条 `MarkType.TAG` 的标记（和书签同一张表、同一套增删改查），额外把「该页开头约 40 字」存进 `snippet` 当卡片摘要；判定「这一页有没有标签」用的是**页区间包含标签偏移**，所以重排后不会丢。手势是 `detectVerticalDragGestures` 驱动一个 0..阈值×1.6 的拉动量，正文用 `graphicsLayer { translationY }` 跟着走（只刷图层、不触发整页重组），顶部的提示用同一个拉动量算 alpha/scale/位移，松手时按是否过阈值决定动作再用弹簧动画回弹；只有「会话认定的当前页」接受这个手势，滑动过程中露出的邻页不会误判。
- **「咚」的音效是自己合成的**：用 Python 合成 22.05kHz/16bit 单声道 wav（低频正弦 + 快速衰减包络 + 3ms 噪声瞬态，18KB）放进 `res/raw/`，运行时用 SoundPool 预加载、走媒体音量播放；没有引入任何音频库或第三方音效素材。
- **朗读要声明软件包可见性**：Android 11 起有包可见性限制，`TextToSpeech` 想找到系统引擎，manifest 里必须有 `<queries><intent><action android:name="android.intent.action.TTS_SERVICE"/></intent></queries>`。这条以前漏了，是「朗读点了没反应」的根因。
- **分页要「算得和画得一样」**：分页器测量文本用的样式必须和渲染时字字一致 —— 首行缩进（`TextIndent`）也要参与测量，否则首行少放两个字、段落多出一行，最后一行就会溢出页面被裁掉半截。另外段落被切开跨页时要用续排标记，让下一页开头那截不再加缩进、不再插段间距。行高取「名义行高」与「实测一行高度」的较大值，再留 1dp 余量。
- **翻页动画的实现**：没有换分页引擎，还是基于 `HorizontalPager`。**平移**什么都不做（pager 默认两页一起动）、**无动画**把 `snapAnimationSpec` 设成 `snap()`。**点击左右边缘和音量键翻页**走 `animateScrollToPage`（带动画），跳转/重排走 `scrollToPage`（直接对齐）—— 用一个「用户主动翻页」的递增序号区分这两种来源。
  > 曾经为了做「覆盖 / 仿真」在这里加过一层「把旧页提到 pager 之上单独画」的实现，v1.6.0 连同这两个效果一起删了：`HorizontalPager` 的绘制顺序按页号递增，页号大的盖住页号小的，「旧页在上」**没法靠改位移实现**，只能绕开引擎另画一层，状态和边界问题成倍增加。**两条教训**：① 页面必须有不透明底色，否则两页会互相透字；② `alpha` 只能用来「让它完全隐形」，绝不能用来「变暗」（半透明一样会透字）。
- **全书页码是真数出来的**：后台用**同一个分页器、同一套排版参数**把每一章排一遍，取每章页数做成前缀和 —— 所以「当前页/总页数」和实际翻页严格一致，不是按字数估算。计算放在 `Dispatchers.Default`（纯排版运算，不碰 UI），并用一个包含字号/行距/边距/字体/缩进/正文区尺寸/章节数的签名去重：排版没变就不重算。代价是首次打开或改完排版后有一两秒没有页码（显示 `—/—`）。
- **分组的数据模型**：书籍库 v2 → v3，新增 `groups` 表 + `books.group_id`（`0` = 未分组），走 `ALTER TABLE` 平滑迁移。**一本书只能属于一个分组**，所以分组是单个外键而不是多对多关系表 —— 这让「移动到分组」「移出分组」都只是一次 `UPDATE`。
- **书架是「分组卡片 + 未分组书」两类混排**：`LibraryStore.ungrouped` 过滤 `group_id == 0`，分组的书只在组内出现，避免同一本书在首页和组里出现两次。
- 应用私有目录里的封面图解码结果按「文件路径 + 最后修改时间」缓存（`CoverCache`），换封面时用一个 version 计数器让全部封面一次性失效，滚动列表不会反复解码。
- **导出没有额外依赖**：`BookExporter` 流式写入（BOM + 逐章标题正文 + CRLF），一份落到 `MediaStore.Downloads`（API ≥ 29）或公共 Download 目录（API ≤ 28），另一份落在 cache 目录并通过 `FileProvider` 分享，全程不读批注表
- **导入这一段不依赖系统选择器的返回值约定**：自己发 `ACTION_OPEN_DOCUMENT`、自己对返回的 Intent 做宽松解析（不看 resultCode，clipData/data/EXTRA_STREAM 都试），并配合「发起前落盘、结果回来清除」的现场标记，来兜住国产 ROM 在后台冻结/清理进程导致的「选完文件没反应」
- release 包**关闭了 R8 压缩**：开发环境没有安卓设备也起不了模拟器（容器不支持 KVM），R8 激进裁剪属于只有真机才暴露的风险，选择完整性优先，代价是包体从 1.3MB 变成约 6.3MB；v1.10.7 引入 pdfbox-android 后再加约 4~5MB
- 构建环境补充：工程目录名含中文时 AGP 会直接拒绝构建，已在 `gradle.properties` 里显式关掉该检查（`android.overridePathCheck=true`），用 Android Studio 或命令行都能正常构建
- 47 个 Kotlin 源文件，约 14291 行

### 已知限制（诚实说明）

1. **只在一台真机上验证过**。开发环境里没有安卓设备和模拟器（容器不支持 KVM），编译、lint、逻辑逐处自审之外，v1.2.1 起都在一台 **vivo V2417A（Android 16）** 上真机安装并实测过：导入（含被系统回收后的自愈）、跨章翻页、按页标签的下拉/取消/目录页签、导出到下载目录、音量键翻页、下拉打标签的手势与音效。**v1.4.0 的封面导入因为 Compose 下拉菜单是独立弹窗、`uiautomator` 抓不到，只做了代码层自审，没有真机点通**（菜单项、裁切界面、存取路径需要你实测一次）。其它品牌 ROM、其它 Android 版本、异形 TXT 的章节识别准确率、特定厂商 TTS 引擎兼容性仍需更多反馈。
2. **`.doc`（97-2003）/ `.mobi` / `.azw3` 等仍不支持**；`.pdf` 只支持**文字版**，扫描件提不出文字（不做 OCR，会明确提示）。
3. **EPUB 章名取不到时会退回书名**：章名优先取 XHTML 里的 `h1~h6`；有些电子书正文里没有标题标签，此时退回该文件的 `<title>` —— 如果那里写的是书名，章名就会是书名（长书名在章节列表里被省略号截断，看起来像「标题被切了」）。
4. **v1.10.7 的四种新格式验证程度不一**：EPUB 和 Markdown 已在真机导入并读过；PDF / HTML 只过了编译与代码自审，还没逐个实测 —— 各格式的内容还原精度（尤其 PDF 的版式与阅读顺序）还需更多样本来验证。
5. **朗读依赖系统 TTS 引擎**，App 不内置语音包。
6. **debug 签名**，不能上架商店。
7. 表格类 docx 会降级成制表符分隔的纯文本，不保留表格线；图片只显示占位符。
8. 导出只写 TXT，不导出 docx；跨章滑动依赖邻章预排，**极长章节（单章十几万字）** 时预排会稍慢一点，首次滑到章末可能有一瞬间的「正在衔接下一章…」。
9. **下滑打标签只在左右翻页模式下有**：上下滚动时下滑是翻正文，两者没法共存；需要的话切回翻页模式。
10. **后台容易被国产 ROM 冻结/清理**：实测这台 vivo 在墨阅退到后台约 5 秒就会 `fast_freezer` 冻结，用「一键清理」会直接杀掉（日志里是 `am_kill ... single-cleaner`）。后果是后台朗读可能被掐断、以及上面说的导入被打断（v1.2.1 已针对导入做了自愈，但把 App 加白名单才是最彻底的）。

# local.properties 里写上你自己的 SDK 路径
./gradlew assembleRelease
