# 墨阅 1.11.23：全面审计与模拟器压力测试

日期：2026-10-24。版本：1.11.23 / 60。仅操作 Pixel_6 模拟器（Android API 37、应用最大 Java 堆 512 MiB）；没有操作用户手机。审查了本轮核心存储、导入、解析、阅读、文件选择、导出、偏好、网络与权限路径。主源码共 73 个 Kotlin 文件、约 2.2 万行；这不是所有路径或全部 Android 系统的形式化证明。

## 确认的问题与修复

| 问题 | 复现或证据 | 修复 |
| --- | --- | --- |
| 大批文件选择导致后台崩溃 | 2000 个长文件名全选后 Home，TransactionTooLargeException，页面状态 1,540,428 字节；原始崩溃日志保留 | 选择及范围候选存为应用私有的原子、不可变草稿；页面状态只存小令牌，兼容旧版小列表；退出清理草稿 |
| 取消导入后仍执行 | 取消后仍生成全部 30 本测试书 | 文件间、读入块、章节提交增加取消检查；不吞 CancellationException；事务回滚当前文件，保留之前完整提交的文件，清理空合并书 |
| 取消搜索后仍扫描 | 取消后继续产生 42 次进度回调 | 每章和命中循环检查取消，取消回调后不再读取下一章 |
| 读取一章会查询全书目录 | chapterText / chapterRich 原先 chaptersOf(...).firstOrNull；全书页数计算会放大为重复全目录查询 | 增加按书籍及章节 ID 的定点查询；批量 ID 查找使用映射；按选择顺序导入跳过无用的自动排序名称扫描 |
| 默认未指定行高会抛异常 | 压力测试 TextStyle 只设字号时，lineHeight.toPx 抛 Only Sp can convert to Px | 先确认单位，再采用字号推算回退行高 |
| 长单段逐页传入全部剩余正文 | 每页 substring(cursor) 及排版重复处理长段落尾部 | 只测量有界前瞻，必要时扩展，保持原文偏移和代理对边界；不是截掉剩余正文 |
| 首次并发导出误报目录创建失败 | 两个并发导出都看到目录不存在，后一 mkdirs 返回 false | mkdirs 后重新确认目录是否已由另一个任务创建 |
| 初始化覆盖快速切章 | 目录已公布但初始批注仍在读取，快速 101 次导航后又被初始化切回开始章 | 首次章节/批注状态在 Main 一起公布；打开进度令牌提前保留，后来的用户导航优先 |

## 已完成的压力边界

- 10000 章识别：每章正文标记一一匹配。
- 200 本固定种子的中、日、英与特殊标题变体：29376 份正文标记保持完整。
- 1050 万字符无标题文本：584 个兜底章节，非空白字符总数不变。
- 1000 个真实 TXT 文件逆序合并：逐章核对来源和正文。
- 千章书 300 次随机正文及样式读取。
- 200 次并发增章和书签切换，检查连续章号、文件唯一、统计和书签结果。
- 50000 个选择 ID 的范围、顺序、追加去重。
- 20000 文件草稿的保存、完整恢复、不可变快照、路径校验和清理；单个状态令牌在 Parcel 中为 180 字节。
- 41.5 万字符的无断行英文、中文及混合 emoji 文本：557 页，字符偏移连续，不切开代理对。
- 201 MiB 源文件按声明大小拒绝，未将其内容装入内存。
- 两千个长文件名通过真实点击全选、Home、后台进程回收、恢复及进入导入确认；修复后没有该次崩溃，原有 396 本模拟器测试书保留。

## 原始证据与复跑

结果与日志：`app/build/audit/full-2026-10-24/`。`baseline-cancellation.txt` 与 `baseline-picker-crash.txt` 是修复前复现；`stress-second.txt` 是修复后的 15 项核心压力结果。`picker-fixed.txt` 和截图是两千文件实际界面验证。后续各套结果、内存采样和最终结论见下。

辅助脚本：`tools/testing/run_full_audit.py`、`tools/testing/full_audit_ui.py`。所有 ADB 操作固定 `emulator-5554`。Android 测试使用独立临时数据库及正文目录，不清空或改写原书架。界面测试不依赖电脑语音服务或真实音频播放。电脑桥的 8 项模拟协议测试另行通过。

## 测试范围的限制

- 仅一个模拟器版本，不代表所有品牌系统、低内存实体机、真实电量/温度、数小时持续音频或后台厂商策略。
- 数据样本为可核对完整性的生成文档；不声称复杂多栏 PDF、扫描 OCR 或任意损坏/加密文档都可读取。当前没有新增 OCR。
- 201 MiB 拒绝测试只验证超限保护；不代表所有小于 200 MiB 的复杂文档都能在 512 MiB 堆内解析。第三方解析器内部的单次重计算不能保证立即中断。
- 内存记录是每两秒左右采样的进程 PSS，不是真实的瞬时峰值；各阶段结束的 Java 堆记录也不是峰值。
- 静态检查的第三方 BouncyCastle TrustManager 警告仍保留；项目代码没有自定义放行任意 HTTPS 证书。此项没有替代完整依赖漏洞扫描。

持续压力共创建并删除 500 本书、3000 章，完成对应的分组、全文搜索、批注和编辑。每轮检查原子正文无孤儿、章节与批注表无残留、分组清空；最终 SQLite integrity_check 为 ok。第一轮到第二十轮，主动 GC 后 Java 堆增长约 0.203 MiB；文件描述符从 98 到 102（包含首次数据库连接初始化），这组有限测试未发现持续增长。此结果不能证明任意时长均无泄漏。

核心压力中的千文件合并约 19.63 秒；千章书 300 次正文加 300 次样式读取约 1.00 秒；41.5 万字符长段落的 557 页分页约 0.668 秒。1050 万字符的完整识别仍需约 37 秒；它在后台线程运行，本次没有声称大书解析已经瞬时完成。

最终静态检查 0 错误、50 条警告、12 条提示。警告主要来自数量文案、可装箱的状态、未用资源、格式化区域设置、同步偏好提交，以及第三方库；保留警告清单，没有用全局屏蔽来制造零警告。

两千文件后台崩溃已在相同模拟器复核消失；实际进程回收后完整恢复选择，取消导入确认后仍回到 396 本书。最终 1.11.23 正常启动，当前进程没有新的致命崩溃；手机没有安装此版。

早期测试脚本中，合并取消点位最初落在第一份文件已经提交之后，现已调整到读取前并重新验证；阅读界面脚本也更新了已改名的语音文案并等待目录关闭动画。这些测试脚本问题不计入应用缺陷。
